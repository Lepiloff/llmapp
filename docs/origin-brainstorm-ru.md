Слово LLM со временем может стать менее массовым. Люди будут говорить “AI apps”, “agent apps”, “assistant apps”. Поэтому в SEO и позиционировании не стоит зажиматься только в “LLM”. Домен остаётся, но контент лучше вести шире.

2. В чём реальная боль пользователя

Сейчас пользователь сталкивается с несколькими проблемами.

Проблема 1. Он не знает, что уже можно подключить к LLM

Например:

можно ли подключить Claude к Asana?
есть ли приложение для ChatGPT, которое помогает искать жильё?
можно ли использовать Gemini с Google Calendar, Photos, Spotify?
существует ли MCP-интеграция для PostgreSQL, Stripe, GitHub, Notion?

Функциональность быстро растёт, но discovery распылён между официальными каталогами, документацией, GitHub, соцсетями и небольшими сторонними директориями.

Проблема 2. Он не понимает разницы между сущностями

Обычному пользователю совершенно неочевидно:

ChatGPT App — это что?
Claude Connector — это аналог?
MCP Server — это для разработчика или тоже можно “установить”?
Interactive Connector в Claude — это полноценное приложение?
Gemini connected app — это внутренняя интеграция Google или маркетплейс?

Твоя платформа может стать местом, где рынок объясняется простым языком.

Проблема 3. Нет нейтрального сравнения

Официальные каталоги будут показывать только свою экосистему:

OpenAI не скажет пользователю: “Для вашей задачи лучше Claude Connector”;
Anthropic не будет ранжировать ChatGPT Apps;
Google не сравнит свои интеграции с MCP.

А LLMAppMarket может.

Я бы завёл на платформе 5 основных типов листингов.

Interactive Claude Apps	Коннекторы, которые рендерят полноценный UI прямо внутри чата

OpenAI строит Apps SDK на базе MCP, Anthropic использует MCP для Connectors и интерактивных приложений, а официальный MCP Registry прямо позиционируется как централизованное хранилище метаданных для публичных MCP-серверов и агрегаторов. Это делает фокус на apps + connectors + MCP наиболее логичным ядром каталога.

9. Какие поля особенно важны для твоего отличия от конкурентов

Главная ценность будет не в том, чтобы написать “это AI app”, а в том, чтобы дать структурированный ответ на вопрос выбора.

Я бы обязательно сохранял:

Поле	Почему важно
Works with	Пользователь хочет знать, совместимо ли с его ассистентом
Read / Write	Одно дело — читать данные, другое — выполнять действия
Interactive UI	Новый важный класс приложений внутри чата
Requires login	Практический фильтр
Required plan	Может работать только на платной подписке
Officially reviewed	Фактор доверия
Open source	Важно для developers
Local or remote MCP	Важная разница для технической аудитории
Last checked	Каталог быстро устаревает

OpenAI, например, отдельно различает сценарии с read/fetch и write-действиями, а Anthropic делает акцент на проверенных каталогом интеграциях и интерактивных приложениях внутри чата. Эти различия стоит отражать прямо в карточке.

12. Источники наполнения каталога
Источник 1. ChatGPT Apps

OpenAI уже принимает приложения в App Directory. В публикационной заявке есть метаданные каталога, MCP connectivity details, доступность по странам и другие параметры — это подтверждает, что экосистема будет структурированной, а значит агрегируемой.

Для MVP:

ручной сбор топовых публично доступных приложений;
страница “ChatGPT Apps Directory — Independent Guide”.
Источник 2. Claude Connectors Directory

У Anthropic уже есть каталог проверенных MCP-интеграций, работающих по всей линейке продуктов Claude. Это прекрасный источник качественных записей для seed-базы.

Источник 3. Interactive Claude Apps

С марта 2026 года интерактивные коннекторы доступны пользователям Claude и позволяют отображать внутри чата доски задач, панели аналитики, дизайн-инструменты и другие живые интерфейсы. Это важная отдельная подкатегория.

Источник 4. Official MCP Registry

Это, возможно, главный технический актив для тебя.

Официальный MCP Registry:

находится в preview;
содержит публичные MCP-серверы;
предоставляет REST API для клиентов и агрегаторов;
использует стандартизированный server.json;
хранит install/configuration metadata.
Практический вывод

Ты можешь сделать автоматический ingest MCP Registry, а затем:

нормализовать данные;
добавить ручную модерацию;
распределить по удобным пользовательским категориям;
добавить объясняющее описание и рейтинговую логику.

Это уже будет ценность поверх сырого реестра.

22. Что может стать твоим moat

Я бы думал о защите не в виде “технологически невозможно скопировать”, а в виде накопленного преимущества.

Со временем moat даст:
структурированная база рынка;
SEO-доменность по запросам вокруг LLM apps / MCP / connectors;
email-аудитория;
отношения с разработчиками;
собственные рейтинги и обзоры;
история обновлений экосистемы;
данные о том, что реально ищут пользователи.

Через год при хорошем исполнении LLMAppMarket может стать не просто каталогом, а отраслевым справочником по app-layer вокруг LLM.

23. Мой окончательный совет

Я бы двигался так:

Немедленно:
поставить простую landing page на домен;
собрать вручную первые 100–150 записей;
утвердить taxonomy и модели данных;
начать разработку каталога.
Первый релиз:
через 4–6 недель;
300+ карточек;
поиск;
фильтры;
15–20 SEO-материалов;
submit form;
newsletter.
Не делать пока:
полноценный marketplace;
оплату;
рейтинги пользователей;
сложные аккаунты.

Сейчас самая сильная версия идеи — это:

“Независимый discovery layer поверх растущей экосистемы LLM Apps.”

И в этом виде проект действительно выглядит своевременным.
